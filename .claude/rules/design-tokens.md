# Дизайн-токены

Направление: **светлый минимализм** — светлый/белый фон, один яркий акцент,
много воздуха, мягкие скругления, аккуратная типографика. Не «космос», но
узнаваемо и дорого. Не Яндекс, не клон.

## Согласовано с Eugene (2026-07-13)

- **Акцент — изумрудно-зелёный.** `--primary` в `src/index.css`:
  светлая тема `oklch(0.596 0.145 163.225)` (≈ Tailwind `emerald-600`),
  тёмная тема `oklch(0.696 0.17 162.48)` (≈ `emerald-500`, ярче — иначе
  тухнет на тёмном фоне). `--ring` — на полтона светлее `--primary` в обеих
  темах, для видимого фокус-ринга. `--sidebar-primary`/`--sidebar-ring`
  зеркалят те же значения (компонент пока не используется, но токены не
  должны противоречить друг другу, когда он появится).
- **Скругления — мягкие, дефолт shadcn не менялся.** `--radius: 0.625rem`,
  шкала `--radius-sm/md/lg/xl/2xl/3xl/4xl` уже выведена из него в
  `@theme inline`.
- **Шрифт — Geist**, без изменений (уже был подключён через preset Nova).

## Важно: `--primary` ≠ `--accent`

В токенах shadcn есть переменная `--accent`, но это **не** «наш акцентный
цвет» — это нейтральный служебный токен для мягких hover/highlight-фонов
(dropdown-пункты, sidebar-hover и т.п.), сознательно оставлен серым
(`oklch(0.97 0 0)` светлая / `oklch(0.269 0 0)` тёмная). Не путать и не
перекрашивать в зелёный — все внутренние hover-состояния перекрасятся заодно,
получится каша.

Продуктовый «акцентный цвет» (кнопки, активные элементы, будущие статусы
поездки) — это **`--primary`**. Кнопка `default`-варианта (`components/ui/button.tsx`)
уже берёт его через `bg-primary text-primary-foreground`, ничего чинить не
нужно.

## Правила

- Все цвета — через CSS-переменные в `src/index.css` (`@theme inline` блок),
  не хардкодить hex/oklch в компонентах.
- shadcn/ui компоненты (`src/components/ui/`) не патчить точечными
  инлайн-стилями — если токенов не хватает, добавлять новую CSS-переменную.
- Скругления — единая шкала через `--radius`, не свои произвольные значения.
- Тёмная тема (`.dark`) обновлять синхронно со светлой при добавлении новых
  токенов — не оставлять расхождений (уже так и было: `--sidebar-primary` в
  тёмной теме был случайно синим из дефолтного preset, поправили заодно).

## `.dark` реально достижима из приложения (с 2026-07-25)

`.dark`-токены были определены с самого начала (2026-07-13), но до
Настроек профиля (`app/ThemeProvider.tsx`, см. `decisions.md`) ничего в
приложении не переключало класс `.dark` — тема была всегда светлой на
практике. Теперь пользователь реально может включить тёмную тему через
Профиль → Настройки, так что расхождения между `.dark`- и
светлыми-токенами больше не гипотетический риск «на будущее», а
видимый баг, если появится.

## Карта тоже следует теме (с 2026-07-25)

MapTiler-стиль карты переключается вместе с `.dark` (светлый `basic-v2` /
тёмный `basic-v2-dark`, см. `decisions.md`). Route-line и маркеры уже были
на CSS-переменных (`var(--foreground)`, `var(--primary)`,
`var(--destructive)`) — карта не исключение из правила «цвета только через
переменные», просто добавляется внешний ассет (стиль MapTiler), который
переключается отдельно, а не хардкодится.
