# Roadmap — архив «Готово»

Подробные записи по каждому завершённому пункту `docs/roadmap.md` — что
именно сделано, какие файлы/паттерны, как проверено в браузере. Вынесено
сюда при компакте 2026-07-23, когда список «Готово» разросся настолько, что
занимал основную часть токенов при чтении `roadmap.md` — сам файл
предназначен для быстрой навигации по плану, а не как ADR-лог (для решений
и их «почему» — `decisions.md`).

---

- [x] Каркас: Vite + React + TS + Tailwind + shadcn/ui + RTK + MSW + XState +
      MapLibre + Motion + PWA-плагин. Память проекта (CLAUDE.md/rules/docs).
- [x] Дизайн-токены: изумрудный `--primary`, мягкие скругления (дефолт),
      Geist. Детали и точные oklch-значения — `.claude/rules/design-tokens.md`.
- [x] Машина состояний заказа (XState, `features/order-flow`) + пустой экран
      карты (`shared/map/MapCanvas`, demo-style MapLibre без ключа) +
      dev-only debug-панель для прогона состояний. `screens/order/OrderScreen`
      подключён в `App.tsx`. Проверено в браузере (Playwright) — полный цикл
      idle → ... → done → RESET → idle без новых консольных ошибок.
- [x] Реальный MapTiler style (`basic-v2`) вместо demo-style + rAF-трекинг
      маркера водителя по полилайну (`useAnimatedPosition`,
      `useRideAutomation`) с throttled-синком в XState-контекст и
      `map.fitBounds()` по текущему отрезку маршрута. Проверено в браузере —
      маркер виден на всём протяжении обеих ног (`enRoute`/`inRide`).
- [x] Класс такси / выбор точки подачи: центр-пин + drag карты для точки
      назначения, bottom-sheet (Motion) с классами и MSW-ценой от расстояния
      A→B. Первый реальный RTK Query api-slice (`entities/ride-class`) —
      warning про пустой store наконец исчез. Пины A/B + линия маршрута на
      карте. Проверено в браузере — drag, реальный сетевой запрос через MSW,
      полный цикл до `searchingDriver`, без консольных ошибок.
- [x] Поиск машины / назначение водителя: `entities/driver` +
      `DriverSearchPanel` (MSW-задержка ~1.5–2.5с, ~20% случайных отказов с
      кнопкой «Повторить поиск») + `DriverCard` (аватар-инициалы, машина,
      номер, рейтинг — держится на экране до `inRide`). Debug-панель для
      `searchingDriver` заменена настоящим UI. Проверено в браузере — 4
      прогона, все 3 демо-водителя из пула встречались, ноль консольных
      ошибок.
- [x] Поездка в реальном времени: `driverAssigned → enRoute` — автоматически
      через 2с, `enRoute`/`inRide` авто-завершаются, когда трекинг доезжает
      до конца ноги (`useRideAutomation`), `arrived → inRide` остаётся
      осознанной кнопкой «Начать поездку». Статус-текст в `DriverCard`
      («Едет к вам», «Ждёт у подъезда» и т.д.). Цена фиксируется при
      подтверждении класса, а не пересчитывается по приезду. Debug-панель
      для всех четырёх состояний заменена настоящим UI. Проверено в
      браузере — полный автоматический цикл без лишних кликов, статусы
      меняются по расписанию, ноль консольных ошибок.
- [x] Оплата / оценка поездки: `RideCompletionSheet` — чек (водитель,
      расстояние, цена), выбор способа оплаты (карта/наличные, реально
      влияет на `PaymentInfo.method`, раньше было захардкожено), звёздный
      рейтинг (1–5, раньше всегда слался фиксированный `DEMO_RATING`).
      Оплата и рейтинг — независимые блоки, можно завершить в любом
      порядке (как и раньше в машине). `RideDoneCard` — закрывающий экран
      с «Заказать снова». Debug-панель теперь обслуживает только `idle`.
      Проверено в браузере — полный цикл чек → оплата (наличные) →
      рейтинг (3 звезды) → авто-переход в `done` → сброс в `idle`, ноль
      консольных ошибок.
- [x] Профиль пользователя + навигация: первый второй экран. Лёгкая
      навигация без роутера (`app/navigationContext` + `NavigationProvider`,
      `Screen = 'order' | 'profile'`), `OrderFlowProvider` поднят в `App`.
      `entities/user` (MSW-мок профиля), `ProfileScreen` (аватар-инициалы,
      имя, телефон, рейтинг пассажира, способ оплаты). Вход в профиль —
      аватар-кнопка на `idle` (`IdleOverlay`), там же настоящая кнопка
      «Начать заказ» — закрыт прод-пробел, debug-панель удалена целиком.
      `InitialsAvatar` вынесен в `shared/ui`. Проверено в браузере —
      idle → профиль → back → заказ, полный флоу цел, ноль ошибок.
- [x] История поездок: третий экран (`RideHistoryScreen`), вход — строка в
      профиле. `entities/ride-history` (статичный MSW-мок, 5 записей с
      адресами/датами/классами/ценами/водителями/оценками). `Screen`
      расширен до трёх, навигация плоская без стека. Проверено в браузере —
      профиль → история → back → профиль → back → заказ, ноль ошибок.
- [x] PWA-полировка: манифест «Такси» + изумрудные иконки
      (192/512/maskable/apple-touch, белый глиф машины) вместо пустого
      `icons: []` и фиолетового favicon от скаффолда. theme-color/apple-меты
      в `index.html`. Offline трёхуровневый: precache оболочки, runtime-кэш
      тайлов MapTiler, баннер-индикатор (`OfflineBanner`/`useOnlineStatus`).
      Проверено (Playwright) — манифест/иконки/SW по `preview`, баннер
      toggle по `dev`. Иконку на телефоне глазами смотрим на хостинг-шаге.
- [x] Реальная геолокация + модель «Я»≠A: новый шаг `selectingPickup`
      (`idle → selectingPickup → selectingDestination → …`),
      `shared/lib/useCurrentPosition` (Geolocation API, fallback `DEMO_PICKUP`
      при отказе, `jumpTo` к точке). Метка «Вы здесь» (`variant: 'dot'`)
      отдельно от точки подачи A. Заодно фикс бага «метку A не видно» —
      центр-пин перекрашен в изумруд (был чёрным поверх чёрной A). Проверено
      (Playwright, mock-геолокация) — success + fallback пути, метка A видна,
      полный цикл, ноль ошибок.
- [x] Геолокация сразу при входе в приложение (полная модель Яндекса):
      `PickupResolver` (переим. из `SelectingPickupControls`) монтируется
      на `idle` И `selectingPickup`, а не только на последнем — запрос
      геолокации стартует, как только открылось приложение, «Я»-dot виден
      уже на `idle`. Точка A выставляется и сразу подтверждается
      автоматически (`CONFIRM_PICKUP` без кнопки) — в типичном случае
      `selectingPickup` не виден пользователю вообще.
      `SET_USER_LOCATION`/`SET_PICKUP` подняты в top-level `on` машины.
      Заодно убрана дохлая кнопка «Назад» (`BACK_TO_PICKUP`) — стала
      no-op'ом после авто-подтверждения, нашли Playwright-проверкой.
      Проверено (Playwright) — success/fallback пути + два полных цикла
      заказа подряд (регрессия «геолокация не переспрашивается на втором
      заказе»), ноль консольных ошибок.
- [x] Такси едет по дорогам, не напрямую: `shared/map/routingApi` (RTK
      Query к реальному OSRM demo-серверу, вне entities/MSW) даёт
      road-геометрию; и линия маршрута (`OrderScreen`), и анимация маркера
      (`useRideAutomation`, обе ноги enRoute/inRide) едут по дорогам.
      Дедуп запроса pickup→dest между линией и анимацией, fallback на
      прямую при недоступности OSRM (`roadOrStraight`), запрос только
      после подтверждения Б (не на drag). Линия сплошная тёмная (убран
      пунктир). Проверено (Playwright, реальная сеть) — изгибы по улицам,
      обе ноги, fallback с заблокированным OSRM, 0 флуда, ноль ошибок.
- [x] Bottom sheet выбора точки Б в стиле Яндекса: `DestinationSheet`
      (сменил `SelectingDestinationControls`) — инпут адреса + список
      (недавние адреса `entities/recent-place` или live-поиск через
      реальный MapTiler Geocoding, `shared/map/geocodingApi`). Тап по
      адресу — `jumpTo` карты + сворот плашки; «Подтвердить» по-прежнему
      читает центр карты. Настоящий drag пальцем (Motion `drag="y"`,
      снап `peek`/`expanded` по velocity/позиции) — закрыт backlog-пункт
      «drag-to-snap физика». Плашка отъезжает вниз (`retreated`) при
      взаимодействии с картой и возвращается в состояние **до**
      взаимодействия (не всегда `peek`). Reverse-геокодинг адреса A в
      шапке и адреса центра карты в инпут (только вне фокуса). Fallback —
      геокодинг недоступен → выбор точки drag'ом карты работает всегда.
      Проверено (Playwright, реальная сеть MapTiler) — реальные результаты
      поиска, недавние адреса кликабельны, свайп снапит, retreat/restore
      подтверждён реальным mouse-drag по карте, fallback с заблокированным
      geocoding доходит до `selectingClass`, ноль ошибок.
- [x] Камера следит за едущим такси: `shared/map/useMapCameraFollow`
      (вызывается из `OrderScreen`, `MapCanvas` больше не управляет
      камерой) — throttled `fitBounds` (~раз в секунду), кадр «такси +
      следующая точка» в движении (`enRoute`: такси+A, `inRide`: такси+Б),
      [A,Б] на выборе класса/ожидании водителя. Ручной drag/zoom
      приостанавливает слежение, автовозврат через 4с бездействия, без
      кнопки recenter. Заодно найден и исправлен реальный баг (и в этом
      хуке, и в уже смёрженном `DestinationSheet`): гейт на `originalEvent`
      в обработчике `moveend` ошибочно блокировал автовозврат/restore при
      быстром флик-драге — MapLibre после инерционного доторможения шлёт
      финальный `moveend` без `originalEvent`. Проверено (Playwright,
      реальная сеть) — [A,Б] в кадре на выборе, слежение в движении,
      override не борется с жестом, автовозврат подтверждён polling'ом
      `window.__map` (дев-only тест-хук), ноль ошибок.
- [x] Убран стартовый экран «Начать заказ»: `selectingPickup` — первый
      интерактивный экран (`initial` машины, `idle`-состояния больше нет).
      Центр-пин = точка A (тот же паттерн, что `DestinationSheet` для Б),
      `moveend` → `SET_PICKUP`; новый компактный `PickupSheet.tsx` (пилюля
      адреса + «Куда едем?» → `CONFIRM_PICKUP` + недавние адреса → `jumpTo`
      + `CONFIRM_PICKUP`, ведёт на `selectingDestination` с центр-пином Б
      уже на адресе). `PickupResolver.tsx` стал headless-сидером геолокации
      (без авто-`CONFIRM_PICKUP`). `ProfileButton.tsx` — аватар вынесен из
      удалённого `IdleOverlay`. `PlaceRow.tsx` — общая строка адреса,
      расшарена с `DestinationSheet`. Два реальных бага найдены и
      пофикшены по ходу (Playwright): непрокапанный список закрывал
      центр-пин собой (`max-h-[45vh]` + внутренний скролл), и `jumpTo` при
      выборе недавнего адреса корраптил `pickup` координатами Б через ещё
      смонтированный `moveend`-listener (`isLeavingRef`-гард). Подробности
      — `decisions.md` (2026-07-23). Проверено Playwright (реальные GPS/
      OSRM/geocoding): нет «Начать заказ», драг двигает A, оба пути на Б
      работают, сквозной smoke до `selectingClass` с road-геометрией,
      `CANCEL_RIDE` возвращает на рабочий экран A, аватар → профиль, ноль
      ошибок.

- [x] Коммитируемая регресс-сеть на `@playwright/test`: `e2e/` (три спека —
      `smoke`, `pickup-destination`, `full-ride`), `npm run test:e2e`
      обязателен перед каждым коммитом наравне с build+lint. Цель — `npm
      run dev` (не preview/prod): дев-хук `window.__map` для проверки
      маршрута/камеры существует только в dev, MSW одинаков во всех
      средах. Внешние API (OSRM/MapTiler) мокаются через MSW

      `roadOrStraight()` тест ловит корректно. Playwright MCP обсуждали

      Подробности обоих (регресс-сети и CI) — `decisions.md` (2026-07-25).
