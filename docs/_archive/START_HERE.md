## О проекте

Делаем **аналог приложения для заказа такси** (в духе Яндекс Такси, но **не клон** —
свой минималистичный дизайн, отдалённо напоминающий, без копирования 1:1).

Ключевая рамка: это **витрина**, которую заказчик (Миша) будет кому-то показывать.
Приложение **не обязано быть полностью рабочим бэкенд-продуктом**. В первую очередь важно,
чтобы фронт **выглядел дорого и убедительно работал**. Но делаем **грамотно**: сначала
архитектура, потом **фича за фичей** с явным сайн-оффом между шагами.

## Зафиксированные решения (не пересматривать без запроса)

- **Стек:** Vite + React + TypeScript + Redux Toolkit (RTK Query) + **MSW** (мок-слой) +
  **XState** (машина состояний заказа) + Tailwind + **shadcn/ui** + **Motion** (ex-Framer Motion).
- **Карта:** **MapLibre GL** + бесплатные векторные тайлы (MapTiler free или свой стиль).
  Полный контроль над видом через `style.json`; ноль возни с брендингом/условиями Yandex.
- **Платформа:** **mobile-first** адаптив (десктоп — бонус, не наоборот), **PWA** для вида
  «настоящего приложения». Показывать в мобильном вьюпорте / с телефона.
- **«Работает» = моки, без бэкенда.** MSW перехватывает сеть и имитирует поведение: задержку
  «ищем машину», смену статусов заказа, тикающую геопозицию водителя. Фронт пишем честно
  (RTK Query, реальные loading/error), бэк выключаемый одним флагом.
- **Дизайн:** свой, минималистичный, «в духе такси, но не Яндекс». Дизайн-направление и токены
  **ещё предстоит определить самим** — см. открытые вопросы.

## Что ещё НЕ решено — обсудить с Eugene ДО скаффолда

1. **Дизайн-направление и токены.** Палитра, типографика, скругления, «характер». Не космос,
   но узнаваемо и аккуратно. Нужно 1-2 референса или согласовать направление.
2. **Объём экранов для демо.** Один вылизанный end-to-end флоу заказа, или широкий охват
   (профиль, история поездок, оплата, экран водителя в пути, выбор класса)? Зависит от аудитории.
3. **Кто аудитория показа** (инвестор / клиент Миши / тендер) — от этого приоритет: глубина
   одного вау-флоу vs широта.
4. **Движение по карте:** реальные маршруты (routing API) или фейковая интерполяция маркера
   по заранее заданному полилайну через `requestAnimationFrame`? Для витрины интерполяция дешевле
   и смотрится как трекинг вживую.

## Дисциплина памяти и воркфлоу (как ведём проект в CC)

Claude Code стартует каждую сессию с чистого контекста. Знание переносится через **файлы**:

- **`CLAUDE.md`** — тонкий индекс, грузится каждый ход. Держать **под ~200 строк**. Сюда:
  стек, команды (dev/build/test/lint), 5-7 жёстких правил, `@`-ссылки на глубокие доки.
  **НЕ** сюда: план, чеклисты, длинные объяснения (тонут и раздувают контекст).
- **`.claude/rules/*.md`** — path-scoped и тематические правила, подтягиваются по релевантности.
- **`docs/`** — глубокие доки: `architecture.md`, `decisions.md` (ADR-лог «почему так»),
  `roadmap.md` (фича-за-фичей план — план меняется, потому НЕ в CLAUDE.md).
- **Auto memory** — CC ведёт сам (грабли, замеченные предпочтения). Проверять через `/memory`.
- **Правило:** CLAUDE.md = «существительные» (что/где), slash-команды = «глаголы» (как делать).

Рабочий цикл:
- **Plan mode перед любой нетривиальной задачей** (Shift+Tab → прочитать план → апрув → эдиты).
- Заканчивать задачи проверкой: «прогони тайпчек и тесты, почини падения».
- Архитектурные решения фиксировать в `docs/decisions.md`, не устно.
- Раздулся CLAUDE.md > ~200 строк → выносить в `.claude/rules/`.

**Фаза 1 — структура.** Предложи дерево папок проекта + скелет памяти (`CLAUDE.md`,

1. Подними каркас Vite + React + TS (+ Tailwind, RTK, MSW, XState, MapLibre, Motion, PWA-плагин).

3. Запусти `/init` поверх, затем **обрежь** результат вдвое (выкинь то, что ловит линтер).
4. Закоммить.

**Фаза 3 — инструменты (MCP / skills).** Обсудить и поставить только нужное — см. **Приложение A**.

## Приложение A — инструменты для CC (наши размышления)

Разбирали список сохранённых Eugene инструментов. Вердикты под ЭТОТ проект
(greenfield, фронт-витрина, mobile-first):

**Ставим:**
- **Context7 MCP** — свежие версионные доки библиотек в промпт. Спасает от галлюцинаций
  устаревших API React/RTK/Vite/MapLibre. Ставить первым.
- **Один браузерный тул** — чтобы CC видел отрендеренный UI и чинил визуал. Бери
  **Playwright CLI как skill** (та же движка, что Playwright MCP, но ~4x меньше токенов;
  Microsoft сам это рекомендует). Chrome DevTools MCP — если понадобится отладка
  network/performance. **Не** держать несколько браузерных тулов сразу — жрут контекст.

**Опционально / по ситуации:**
- **find-skills** (`npx skills` / skillkit / findskills) — мета-поиск по маркетплейсам скиллов.
  Прогнать **один раз** в начале для разведки, потом снести. Осторожно: тянет community-скиллы
  неизвестного качества.
- **Ponytail** — скилл «ленивого сеньора» (YAGNI, минимум кода). ⚠️ Конфликтует с задачей
  «вылизанный UI»: его инстинкт — нативный `<input>` вместо компонента. Максимум — **lite**,
  либо просто строка «YAGNI, prefer minimal solutions» в CLAUDE.md. **ultra не брать.**
- **Glif MCP** — генерация картинок/мемов через glif.app. Пригодится на плейсхолдеры (аватары
  водителей, машины, баннеры). Но проще генерить ассеты напрямую. Опционально.
- **Markitdown** (Microsoft) — конвертит PDF/docx/pptx → Markdown для скармливания CC.
  Нужно, только если Миша даст спеку/бриф в PDF. Ситуативно.

**Пропускаем сейчас:**
- **Perplexity MCP** — дубль встроенного WebSearch/WebFetch у CC. Лишний ключ и контекст.
- **Graphify** — граф знаний по кодбазе. Оверкилл для greenfield; ценно на тысячах файлов.
- **Headroom** (компрессор контекста) — чистая экономия токенов, для маленькой фронт-витрины
  не нужен. (Отдельный вариант «Headroom» — statusline-бар заполнения контекста в CC — дешёвый
  QoL, но не обязателен.)

**Важнее любого MCP** (рычаги, которые реально двигают демо):
- Дизайн-система (**shadcn/ui + Tailwind + токены**) — рычаг №1 для «выглядит дорого».
- **MSW** — «работает как настоящее» без бэкенда.
- **XState** — флоу заказа, который не разваливается при клик-туре.
- **Motion** — анимации, которые продают таксишку (bottom-sheet, машинка по маршруту, статусы).
- Аккуратный **CLAUDE.md** с токенами и архитектурой перебивает половину списка выше.

Минимальный стартовый сетап тулов: **Context7 MCP + Playwright CLI-skill + правильный CLAUDE.md.**
Остальное — по мере надобности.

## Приложение B — юр-флажок по картам

MapLibre выбран в т.ч. чтобы не залезать в условия Yandex Maps. Если когда-нибудь вернёмся
к **Yandex JS API** ради узнаваемости: он бесплатен при соблюдении условий (суточные лимиты,
для демо хватает), но **бесплатная оферта запрещает строить конкурирующий картографический/
навигационный сервис и требует не прятать брендинг Yandex**. «Заказ такси» обычно не конкурент
картам, но раз это показывают/продают — перед продакшеном глянуть оферту, чтобы не подставить Мишу.
