# Roadmap

Фича за фичей, план меняется по ходу — не хранить в CLAUDE.md. Порядок —
рабочая гипотеза, пересматривать при новых вводных от Eugene/Миши.

Каждый пункт — отдельная `feature/<slug>` ветка, план-mode перед стартом,
явный аппрув перед мёржем в `main` (см. `.claude/rules/git-workflow.md`).

## Готово

- [x] Каркас: Vite + React + TS + Tailwind + shadcn/ui + RTK + MSW + XState +
      MapLibre + Motion + PWA-плагин. Память проекта (CLAUDE.md/rules/docs).
- [x] Дизайн-токены: изумрудный `--primary`, мягкие скругления (дефолт),
      Geist. Детали и точные oklch-значения — `.claude/rules/design-tokens.md`.
- [x] Машина состояний заказа (XState, `features/order-flow`) + пустой экран
      карты (`shared/map/MapCanvas`, demo-style MapLibre без ключа) +
      dev-only debug-панель для прогона состояний. `screens/order/OrderScreen`
      подключён в `App.tsx`. Проверено в браузере (Playwright) — полный цикл
      idle → ... → done → RESET → idle без новых консольных ошибок.
- [x] Реальный MapTiler style (`basic-v2`) вместо demo-style + rAF-трекинг
      маркера водителя по полилайну (`useAnimatedPosition`,
      `useRideAutomation`) с throttled-синком в XState-контекст и
      `map.fitBounds()` по текущему отрезку маршрута. Проверено в браузере —
      маркер виден на всём протяжении обеих ног (`enRoute`/`inRide`).
- [x] Класс такси / выбор точки подачи: центр-пин + drag карты для точки
      назначения, bottom-sheet (Motion) с классами и MSW-ценой от расстояния
      A→B. Первый реальный RTK Query api-slice (`entities/ride-class`) —
      warning про пустой store наконец исчез. Пины A/B + линия маршрута на
      карте. Проверено в браузере — drag, реальный сетевой запрос через MSW,
      полный цикл до `searchingDriver`, без консольных ошибок.
- [x] Поиск машины / назначение водителя: `entities/driver` +
      `DriverSearchPanel` (MSW-задержка ~1.5–2.5с, ~20% случайных отказов с
      кнопкой «Повторить поиск») + `DriverCard` (аватар-инициалы, машина,
      номер, рейтинг — держится на экране до `inRide`). Debug-панель для
      `searchingDriver` заменена настоящим UI. Проверено в браузере — 4
      прогона, все 3 демо-водителя из пула встречались, ноль консольных
      ошибок.
- [x] Поездка в реальном времени: `driverAssigned → enRoute` — автоматически
      через 2с, `enRoute`/`inRide` авто-завершаются, когда трекинг доезжает
      до конца ноги (`useRideAutomation`), `arrived → inRide` остаётся
      осознанной кнопкой «Начать поездку». Статус-текст в `DriverCard`
      («Едет к вам», «Ждёт у подъезда» и т.д.). Цена фиксируется при
      подтверждении класса, а не пересчитывается по приезду. Debug-панель
      для всех четырёх состояний заменена настоящим UI. Проверено в
      браузере — полный автоматический цикл без лишних кликов, статусы

- [x] Оплата / оценка поездки: `RideCompletionSheet` — чек (водитель,
      расстояние, цена), выбор способа оплаты (карта/наличные, реально

      рейтинг (1–5, раньше всегда слался фиксированный `DEMO_RATING`).

- [x] История поездок: третий экран (`RideHistoryScreen`), вход — строка в

- [x] PWA-полировка: манифест «Такси» + изумрудные иконки

- [x] Реальная геолокация + модель «Я»≠A: новый шаг `selectingPickup`

      `shared/lib/useCurrentPosition` (Geolocation API, fallback `DEMO_PICKUP`
      при отказе, `jumpTo` к точке). Метка «Вы здесь» (`variant: 'dot'`)
      отдельно от точки подачи A. Заодно фикс бага «метку A не видно» —

      полный цикл, ноль ошибок.
- [x] Геолокация сразу при входе в приложение (полная модель Яндекса):
      `PickupResolver` (переим. из `SelectingPickupControls`) монтируется
      на `idle` И `selectingPickup`, а не только на последнем — запрос
      геолокации стартует, как только открылось приложение, «Я»-dot виден
      уже на `idle`. Точка A выставляется и сразу подтверждается
      автоматически (`CONFIRM_PICKUP` без кнопки) — в типичном случае
      `selectingPickup` не виден пользователю вообще.
      `SET_USER_LOCATION`/`SET_PICKUP` подняты в top-level `on` машины.
      Заодно убрана дохлая кнопка «Назад» (`BACK_TO_PICKUP`) — стала
      no-op'ом после авто-подтверждения, нашли Playwright-проверкой.
      Проверено (Playwright) — success/fallback пути + два полных цикла
      заказа подряд (регрессия «геолокация не переспрашивается на втором
      заказе»), ноль консольных ошибок.
- [x] Такси едет по дорогам, не напрямую: `shared/map/routingApi` (RTK

      Дедуп запроса pickup→dest между линией и анимацией, fallback на

      после подтверждения Б (не на drag). Линия сплошная тёмная (убран
      пунктир). Проверено (Playwright, реальная сеть) — изгибы по улицам,
      обе ноги, fallback с заблокированным OSRM, 0 флуда, ноль ошибок.

## Дальше

Правки от Eugene по референсу Яндекс.Такси (2026-07-20) — по каждому пункту
сначала обсуждение (может что-то добавить/уточнить), потом отдельный
`feature/<slug>` план как обычно.

1. **Bottom sheet в стиле Яндекса** — инпут адреса точки Б + список
   прошлых точек под ним (сейчас — drag карты с центр-пином). Плашка
   уезжает вниз при взаимодействии с картой, возвращается после паузы.
   Геокодинг — **реальный, MapTiler Geocoding API** (тот же вендор/ключ,
   что и тайлы; отдельный устоявшийся продукт, не путать с
   Directions-beta) — поиск адреса по тексту + реверс-геокодинг текущей
   позиции для показа адреса A текстом.
2. **Камера следит за едущим такси** — авто-fit A+Б на этапе выбора,
   затем на этапах движения — такси + **следующая по флоу точка**
   (`enRoute`: такси+A, `inRide`: такси+Б), с ручным зумом/паном
   пользователя и авто-возвратом через паузу бездействия. Детали паузы
   (сколько сек), кнопка ручного recenter — уточняются в план-mode.

3. **Как Миша будет смотреть демо** — самый последний пункт, после всех
   правок дизайна (от Eugene/Миши). Решить: локальный запуск у него на
   компе (`npm run dev`/`preview`) или залить на бесплатный хостинг, чтобы
   зайти прямо с телефона и потрогать вживую (mobile-first — с телефона
   нагляднее). **Ключевой нюанс:** данные живут на MSW, а MSW гейтится на
   dev (`import.meta.env.PROD` в `main.tsx`) — голая прод-сборка на
   статик-хостинге отдаст красивую устанавливаемую оболочку, но с мёртвыми
   запросами. Варианты: (а) хостить dev/preview; (б) снять dev-гейт с MSW
   специально для демо-сборки (тогда любой статик-хостинг работает целиком,
   как задумано «нет бэкенда = MSW имитирует»). Здесь же — финальная
   проверка PWA-установки с реального телефона. Ещё нюанс: геолокация
   требует secure context (https) — localhost и любой нормальный
   статик-хостинг (Netlify/Vercel/GH Pages дают https) подходят, но по
   http с телефона геолокация молча уйдёт в fallback `DEMO_PICKUP`.
