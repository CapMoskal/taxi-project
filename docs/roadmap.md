2. **Адаптивная вёрстка под десктоп — по референсу реального Яндекс.Такси
   (десктоп, `taxi.yandex.ru`).** Eugene прислал скрин (2026-07-27,
   `taxi.yandex.ru/ru_ru/`, Ростов-на-Дону) и хочет повторить именно этот
   UI/UX-паттерн для десктопа — не абстрактный «адаптив», а конкретная
   референсная раскладка. Сам файл скриншота не сохранён в репозиторий
   (прислан инлайн в чат, не файлом) — если нужно держать его в
   `docs/reference/`, Eugene может скинуть файлом отдельно. Что на скрине
   (текстовое описание для планирования, раз бинарник не сохранён):
   - **Левая панель (фиксированной ширины, не на всю высоту карты)**:
     сверху поля «Откуда»/«Куда?» с ценой/временем справа от «Куда»
     (`24 мин`), под ними «+ Добавить остановку». Ниже — **грид карточек
     класса такси 3×2** (Эконом/Комфорт/Комфорт+ и Business/Детский),
     каждая — иконка машины + название + цена, активная подсвечена.
     Ниже — «Способ оплаты» (иконка+текст+чеврон), «Промокод» (чеврон),
     текстовое поле «Комментарий водителю…», и внизу панели — крупная
     жёлтая кнопка «Заказать» на всю ширину панели.
   - **Правая часть — карта на всё оставшееся пространство экрана**, поверх
     неё (не в панели): зелёная линия маршрута с оранжевыми/красными
     сегментами (загруженность дорог), круглая красная плашка с ETA
     («3 мин») у начальной точки, controls зума в правом нижнем углу.
     Два промо-баннера поверх карты по краям (левый верхний — «заказ такси
     по телефону», правый верхний — «стать водителем») — это
     маркетинг-контент, не обязательно копировать буквально, но задаёт
     ощущение «карта — на весь экран, панель — плавающий слой поверх/сбоку».
   - **Верхний навбар** на всю ширину — лого слева, текстовое меню
     (Пользователям/Водителям/Бизнесу/Партнёрам/Скачать) по центру-справа,
     аватар пользователя в правом углу.
   - Ключевое отличие от текущего мобильного флоу: сейчас на мобильном вся
     последовательность (точка А → точка Б → класс → оплата) — это
     сменяющие друг друга bottom-sheet/полноэкранные шаги поверх карты; на
     десктопе у Яндекса это **одна статичная левая панель**, где всё видно
     сразу (адреса + класс + оплата + кнopka «Заказать» одновременно, без
     пошагового скрытия предыдущих шагов) — это меняет не только CSS
     (медиа-запросы), а вероятно и то, как экран показывает
     XState-снапшот на десктопе (несколько шагов видны одновременно вместо
     одного активного).
   - **Не спланировано пока**: как это ляжет на текущую XState-машину
     заказа (`features/order-flow`) — показывать сразу несколько шагов на
     десктопе быть может потребует по-другому читать `snapshot` в
     `OrderScreen`, а не просто адаптивных классов Tailwind. Это и предстоит
     подробно обсудить в планировании.
   - Про предыдущий (более узкий) запрос — "адаптив только для новых
     страниц профиля или весь флоу" — снят этим более конкретным
     референсом: похоже, что речь именно про весь экран заказа, полностью
     под этот десктопный паттерн. Уточнить явно в начале планирования.
